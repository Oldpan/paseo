# Bigbang Chat 与 Studio 集成 Paseo 路线图

讨论确认日期：2026-10-25。2026-11-14 重排了交付顺序，并改写了外网、通知和定时三项决定。

本路线图记录决定、顺序和每个阶段的当前状态。实测证据按日期记在 [验收记录](bigbang-acceptance.md)；代码存在不等于该阶段完成。

## 产品目标与核心关系

以 Paseo 为运行框架，吸收 Bigbang 已有 Chat、Studio 源码和 UI 设计，构建个人使用的多 Agent 助手产品，同时支持自然聊天和严肃工作。

- **聊天助手**：长期身份，保留人格、私聊、群聊与独立记忆，负责交流、日常工具和任务协调。
- **聊天会话**：用户和聊天助手交流的上下文，可产生严肃任务。
- **严肃任务**：有目标、执行范围和验收要求的工作，由聊天助手在授权范围内发起。
- **工作区 Agent**：严肃任务的独立执行者，拥有自己的工作上下文，负责项目文件和开发命令。
- **Studio**：查看、操作工作区 Agent，以及文件、终端、编辑器和执行过程的工作界面。

自由与严肃之间的切换，表现为持续的 Chat 与独立任务 Studio 之间的切换。聊天助手发起任务后，任务可在后台继续执行，结果回到发起它的聊天。

## 吸收 Bigbang 源码与 UI

以当前 Bigbang 的 `apps/app/src` 为实现来源，`archive/web` 为视觉和交互对照。吸收范围同时包含组件、业务算法、状态行为与已有测试。

| 部分             | Bigbang 吸收方向                                                                                     | Paseo 接入方向                                                                                 |
| ---------------- | ---------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------- |
| Chat 展示        | 直接迁入头像、消息、Markdown、输入框、线程、菜单、主题和相关交互；补充过程步骤单行折叠与待发排队条。 | 模型发现、持续执行会话、运行状态，以及回复中途插话（`steer`）和中断重发。                      |
| Chat 业务        | 私聊、群聊、参与者路由、圆桌、记忆、任务关联和回执合同。                                             | Agent 的创建、续聊、控制及跨机连接。                                                           |
| Studio 组织      | 迁入布局、命名标签组和多机器工作区外框；Mac/Web 多列，Android 单个活动工作区。                       | 工作区内部面板、文件会话、Agent timeline 与执行状态。                                          |
| 文件、Git 和编辑 | 适配外框与主题；Android 迁入本地 CodeMirror/WebView。                                                | 直接复用文件浏览、Changes、Diff、Web/Mac 编辑器；三端统一使用 FileEditorModel 保存与冲突处理。 |
| 终端             | 迁入 xterm 显示、移动辅助键、输入法、选择复制、鼠标和原生 WebView 桥接。                             | 保留 PTY 生命周期、订阅、快照、顺序、背压和尺寸所有权；沿用现有 xterm 版本。                   |
| 执行过程         | 保留任务卡及 Chat/Studio 跳转。                                                                      | 复用 timeline、工具调用和审批控件。                                                            |

按组件及业务模块拆分 Core API、事件和状态依赖，再适配 Paseo。界面验收覆盖布局、字体、配色、间距、动效、输入、焦点、空态、加载、错误和禁用状态。

## 实现约束

- Chat 身份与 Paseo 的执行地址分别保存；每个聊天/线程/助手持久绑定一个执行 Agent，不按消息创建 Agent 或重复灌入历史。单会话上下文达到轮次或体积上限时，自动将阶段摘要写入助手 `MEMORY.md` 并滚动绑定新执行 Agent，Chat 会话 ID 与可见历史保持连续。任务保留独立执行身份。
- 工作区容器固定绑定 `{serverId, workspaceId}`。文件、Git、终端和 Agent 沿用该归属；不同工作区间不移动文件编辑面板。切换 Studio 不改变 Chat 数据源，返回时恢复聊天、草稿与阅读位置。
- Chat 协调模块集中维护路由、任务账本、幂等、取消 fence、freshness 和重启恢复。保持消息入队、执行接收、执行结束、结果送达和验收通过的区别。
- 插件工具调用者由宿主绑定，角色授权不能依赖模型输入或可修改 labels。共享工具目录、HTTP MCP 身份绑定及远端插件调用能力需要核实和扩展。
- 三端实时变化和断线恢复需要带游标的事件合同；`chat.state` 初始快照只下发各会话近期消息窗口，历史记录按会话分页拉取，客户端消息流使用虚拟化列表与按 ID 增量合并。业务状态不从任意模型文本的 JSON 外观推断。
- Android 原生编辑器吸收 Bigbang 的本地 CodeMirror／WebView 能力，适配 Paseo 文件模型、自动保存和冲突处理。
- 保留 provider 的沙箱与审批机制。Spark 已观察到的 Linux 沙箱问题单独诊断，执行审批必须准确关联任务。插件只在已获授权的 Spark 隔离实例启用；不重启官方 6767 daemon，不使用 DevSpace。
- 应用身份、深链、数据目录及更新源覆盖 Mac 和 Android，与官方 Paseo、现有 Bigbang 共存。
- 源码迁入后由 Paseo fork 独立构建，不运行或依赖原 Bigbang Core、Hub、agent-node。Web 随 Spark daemon 自托管，同版本发布，只在局域网和 Tailscale 内访问。
- 自托管 relay、cpolar 域名和真实的后台通知是“手机可用”的验收前置条件。Spark 的启动脚本已单独打开 relay，见 [bigbang-development.md](bigbang-development.md#self-hosted-relay)。

## 参考来源

- **原 Bigbang**：同级目录 `bigbang` 的 `apps/app/src` 是实现来源。Chat 的自由协作、圆桌和 Mailbox 规则来自那里。
- **Grok Bot**：吸收结论在原 Bigbang 的 `architecture/roadmap/chat-native-collaboration-roadmap.md`。这里取它的“对话默认安静、过程按需展开”和工作中补充指令，不取它的内部实现。
- **Muse（Meta）**：取它的收件箱式界面（待批准、活动、即将运行、建议）和“周期任务的结果发在对话里”。它的周期任务被用户反馈不可靠，所以“例行”带连续运行验收。

## 已确认的 UI 与工作区取舍

1. 以 Bigbang 当前 `apps/app` 的整体 UI、Chat 和 Studio 外框为基准，直接迁移源码；旧 Web 代码用于视觉对照。
2. Studio 统一组织多台机器。Mac/Web 支持多列；Android 保持单个活动工作区，通过切换器访问其他工作区。
3. 命名标签组与布局由 Bigbang 外框组织；Paseo 继续拥有工作区内部文件、Git、编辑、执行及审批状态。
4. 终端使用 Bigbang 显示与输入技术，接入 Paseo 现有终端会话；Android 编辑器接入现有文件模型，不增加另一套保存后端。
5. Bigbang 构建只有一个外框：Paseo 首页并入 Studio 首页，打开工作区进入 Studio 列，History、Schedules 与新建工作区在 Bigbang rail 旁显示，主机列在 Member → Machines。对应关系见 [development.md](development.md#bigbang-presentation-migration)。

后续顺序见“交付顺序”。遇到已确认约束之外、无法自行取舍的问题再沟通。
