# Bigbang 例行（Routines）与 Playbook 方案

状态：方案，未实施。2026-11-14 改为复用 Paseo 的定时任务。建立在 [Chat 协调](bigbang-chat.md) 的账本、持久聊天会话与助手机器归属之上；在路线图里的位置见 [交付顺序](bigbang-roadmap.md#交付顺序)。

## 目标

让常驻在 Spark（或在线 member）上的 Chat 助手按时做事：

- **例行（Routine）**：到点唤醒指定助手，在绑定的私聊或群聊里检查、汇总或做日常维护。没事就静默，有结论或异常才发消息并通知你。
- **提醒**：只运行一次的例行，比如“明天下午三点提醒我回邮件”。
- **操作手册（Playbook）**：你带助手走通一次任务后，助手把步骤固化到自己 home 下的 `playbooks/`，以后的对话和例行按手册做。

## 复用 Paseo 定时，只拓展一处

Paseo 的定时任务（`packages/server/src/server/schedule/`）已经有这些，全部沿用：

- 固定间隔和带时区的 cron。
- `maxRuns` 和 `expiresAt`，`maxRuns: 1` 就是一次性运行。
- 暂停、恢复、立即运行一次、运行记录。
- 错过的周期不补跑：daemon 停机重开后只推进到下一次。
- 命令行、客户端 RPC 和 Schedules 页面的表单。

不能把定时直接指向助手的聊天执行 Agent（现有的 `agent` 目标，`service.ts` 的 `executeSchedule`），原因有四个：

1. 提示词不带账本的回合编号，账本不知道有过这一回合，结果进不了聊天。
2. 助手正在回复时这次运行直接失败，不排队。
3. 结果按“最后一条消息”读取，没有锚点，会和下一回合抢。[Chat 协调](bigbang-chat.md#a-turn) 明确不用这种读法。
4. 插件收不到“定时触发了”的事件，没法事后接管。

Paseo 的 heartbeat 也不行：它以用户消息到达，会提前结束有锚点的回合。

所以给定时加一种目标，其他不动：

| 拓展          | 内容                                                                                                                                                        |
| ------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 目标 `plugin` | `ScheduleTargetSchema` 新增 `{ type: "plugin", pluginId, payload }`。Bigbang 的 `payload` 是 `{ assistantId, conversationId, threadId? }`。                 |
| 到点交接      | daemon 调用该插件的处理函数，只做交接，30 秒内返回（插件请求的上限）。巡检回合可能跑几分钟，不能让这次调用一直挂着。                                        |
| 运行结果写回  | 回合结束后，插件把状态和一行摘要写回这次运行记录，Schedules 页面的运行历史才看得到真实结果。                                                                |
| 谁能创建      | 只有客户端 RPC（你本人）和插件自己的宿主调用能创建 `plugin` 目标。Agent 用的 MCP 定时工具不能创建，否则一个 Agent 能冒充别的助手排例行。                    |
| 协议兼容      | 旧客户端解析不了新的目标类型。用 `server_info.features.*` 开关控制，并在读取处加 `COMPAT` 标记，见 [protocol-compatibility.md](protocol-compatibility.md)。 |

这处拓展对任何插件都有用，做完提成上游 PR。

## 一次例行怎么跑

例行的定时存在协调器（Spark）的 daemon 上，助手绑定在哪台机器都一样。

1. **到点**：Paseo 的调度器触发，调用 Bigbang。Bigbang 按账本核对：助手还在、仍是该会话的成员。不满足就把这次运行记为失败并暂停这条定时。
2. **排回合**：在 `(conversationId, threadId, assistantId)` 的持久聊天会话里入队一个 `kind: "routine"` 的回合，提示词标明 `[Routine: <name>]` 和当前时间。助手正在同一会话回复你时，例行回合排在后面，不打断。
3. **上一轮没跑完**：同一条例行的上一个回合还在排队或运行时，这次不再入队，记为跳过。
4. **机器离线**：助手所在的 member 离线时记为跳过（`host_offline`），聊天里不出现报错气泡。
5. **静默**：结果正常时助手只回复 `(pass)`，和群聊的 awareness 回合一样。账本不提交消息，也不通知。
6. **发言**：有结论或异常时，正文作为 `final` 消息提交到会话并触发通知。回合里可以照常用 `bigbang-start_task`、`bigbang-send` 等已授权的工具；遇到审批按原会话流程通知你。

账本里记四种结果，写回定时的运行记录时这样对应：

| 账本结果  | 含义                     | 定时运行记录       |
| --------- | ------------------------ | ------------------ |
| `replied` | 发了消息                 | 成功，摘要是首行   |
| `passed`  | 回复了 `(pass)`          | 成功，摘要“静默”   |
| `skipped` | 上一轮未完或机器离线     | 成功，摘要写明原因 |
| `failed`  | 回合中断、出错或核对不过 | 失败               |

## 操作手册（Playbooks）

每个助手在自己所属机器的 home 目录下维护 `playbooks/` 文件夹（与 `MEMORY.md`、`notes/` 同级，位于 `$PASEO_HOME/bigbang/assistants/<assistantId>/playbooks/`）：

- **怎么生成（“Show-Me” 沉淀）**：用户在聊天或接管过程中带助手做完一件事后，说“把刚才的流程存成 playbook”，助手用自己的文件工具把目标、前置条件、具体步骤、判断标准和“何时调用 `hand_to_user` 交用户处理”写成 `playbooks/<slug>.md`。
- **怎么发现与使用**：助手的系统提示词与 `MEMORY.md` 索引约定一起说明 `playbooks/` 的用途。每当用户要求执行某类常规事务或 Routine 触发时，助手先读对应的 `playbooks/<slug>.md` 按步骤执行；执行中若发现页面结构变化或用户纠正了做法，助手更新该文件。
- **跨机读写**：与 `MEMORY.md` 相同，协调器上的助手直接读写本机文件，member 机器上的助手经扩展后的 `member.memory.*` / `member.playbook.*` 供客户端查看与编辑。

## 工具与界面

### 助手工具（`bigbang-routine_*`）

助手在聊天回合里管理自己名下、当前会话里的例行，所以你可以直接说“每天早上 9 点按 `playbooks/daily-check.md` 帮我看一下，有事叫我”或“明天下午三点提醒我”：

| 工具             | 作用                                                         |
| ---------------- | ------------------------------------------------------------ |
| `routine_list`   | 列出当前助手在本会话（或名下全部）的例行及最近运行结果       |
| `routine_save`   | 在当前会话新建或更新一条属于自己的例行，或建一条一次性的提醒 |
| `routine_delete` | 删除一条属于自己的例行                                       |

这些工具由插件代为创建 Paseo 定时。授权按账本校验：调用者只能操作 `assistantId` 是自己、且自己仍是成员的会话里的例行。例行回合运行期间不能新建例行。

### 界面

- **Schedules 页面**：例行和工作区定时在同一个列表里，例行的目标显示为“助手 · 会话”。暂停、恢复、立即运行沿用现有控件。
- **助手面板**：Memory 标签页旁显示这位助手名下的例行和 Playbooks。
- **收件箱**：“即将运行”一段读属于助手的定时。
- **聊天消息标记**：例行产出的消息带简短标记（如 `Routine · 早间汇总`），和你提问触发的回复区分开。

## 分阶段

| 阶段             | 内容                                                                                      | 验收                                                                                                                      |
| ---------------- | ----------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------- |
| T0 宿主与回合    | 定时的 `plugin` 目标、到点交接、结果写回、`kind: "routine"` 回合、`(pass)` 静默、跳过规则 | 到点自动运行：回复 `(pass)` 时聊天无新气泡且记为 `passed`；有正文时出现在聊天里；一次性提醒只触发一次。连续运行验收见下。 |
| T1 工具与界面    | `bigbang-routine_*` 助手工具、Schedules 页面里的例行、助手面板、消息标记                  | 在私聊里让助手建一条例行和一条提醒，Schedules 页面同步显示，点“立即运行”走通完整回合。                                    |
| T2 Playbook 闭环 | 助手 home 下 `playbooks/` 初始化、提示词引导、界面查看与编辑 Playbook（含 member 机器）   | 带助手跑通一次工作区检查后让它存成 Playbook，之后由例行引用该 Playbook 独立执行成功。                                     |

**连续运行验收**（T0）：一条每小时的例行连续跑 7 天，期间重启一次 Spark 的测试 daemon、让 Mac 离线一次。每一次到点都有一条运行记录，结果是 `replied`、`passed`、`skipped`、`failed` 之一，没有无声丢失，也没有同一周期跑两次。Muse 的用户反馈过周期任务不可靠，这条验收针对的就是它。
