# Bigbang 手机控制方案

状态：方案，未实施（2026-11-02）。设计参考 [wangzan101/mika](https://github.com/wangzan101/mika)（Apache-2.0，与 Paseo 相同）的手机控制部分。

## 目标

Chat 助手（Spark 或 Mac 上的 Codex、Claude、Grok）能看到 Android 手机的画面并操作手机 App。电脑和手机上的 Chat 都能发起。被控手机是 Android 14 及以上；iPhone 不能被控（系统不允许读、操作别的 App），只能当 Chat 客户端。

例子：“看看微信群今天聊了什么”“在小红书上看这个博主最近发了什么”“给文件传输助手发一句话”。

## 结构

```
Chat 助手（Spark）
  └─ bigbang-phone_* 工具（Bigbang 插件，协调器上）
       └─ 指令队列（协调器账本）
            └─ 手机上的 Paseo App：长轮询取指令、回传结果
                 └─ 原生模块 paseo-phone：内置助手（shell 身份）+ 后台虚拟屏 + 无障碍
```

### 谁做决策

Chat 模型自己一步一步看、一步一步点，不在手机上另跑一个模型。这样助手能看到手机画面，回复里能讲清楚它看到了什么。往返次数靠复合工具压下来（见 P2）。

另一种做法是把 mika 整个装上，助手把“一件事”交给 mika，由 mika 自己的模型去办。它更快能用，但 Chat 模型看不到画面，不符合目标，不选。

## 手机端

在 `packages/app/modules/paseo-phone` 新建 Expo 原生模块（Kotlin），从 mika 挑着移植：

| mika 位置        | 内容                                                                                                       | 规模（行） |
| ---------------- | ---------------------------------------------------------------------------------------------------------- | ---------- |
| `core/adb`       | 自实现的 ADB 协议、无线调试配对、配对钥匙                                                                  | ~1,500     |
| `app/cap/phone`  | 内置助手（经无线调试以 shell 身份起 `app_process`，AIDL 交接）、虚拟屏、无障碍读控件树和做手势、被杀后恢复 | ~8,700     |
| `core/uistate`   | 控件树、元素编号与过期检测、等界面稳定、动作效果判定                                                       | ~4,600     |
| `core/cap/phone` | 手机工具逻辑、手势和打字节奏                                                                               | ~2,700     |
| `app/takeover`   | 接管：App 挪到主屏给用户处理，再挪回                                                                       | ~400       |

合计约 1.8 万行。mika 的主循环、上下文、记忆这些不移植，Chat 模型那边已经有了。

- **配对一次**：用户在手机上打开无线调试，配对码可以由无障碍服务从设置页读出。换 Wi-Fi 或重启后无线调试会被系统关掉，内置助手在用户授权后自动重新打开。
- **虚拟屏**：Android 14 起虚拟屏有自己的焦点，助手操作时你照常用手机，包括在 Paseo 里看 Chat。
- **前台服务**：手机控制开着时有一条常驻通知，上面能直接关掉。它也让进程不被杀，JS 里的 daemon 连接继续工作。
- **文字识别**（已定：先不做）：mika 在控件树读不全时用 ML Kit 补读。我们先只靠控件树和截图，控件树读不全的界面（自绘界面、游戏）由模型看截图判断。ML Kit 是 Google 闭源库，以后要加，F-Droid 构建（`PASEO_FDROID_BUILD=1`，见 [android.md](android.md)）要去掉它。mika 判断控件树够不够用的规则（`core/uistate/TreeQuality.kt`）照样移植，读不全时提示模型看截图。

移植的文件保留 mika 的版权头，并在 NOTICE 里加一条。

## 连接

插件不能向客户端推送，所以由手机来取：

- 手机长轮询协调器上的插件 RPC：`phone.commands.next` 挂 20 秒等指令，`phone.commands.result` 回传结果。和 Chat 的 `chat.state` 同一种做法。
- 这条路走 Paseo 现有的连接，但只在局域网里接受控制（已定）：手机只在用局域网直连协调器时取指令，经 relay 连着时不取。Chat 本身经 relay 照常能用，只是手机工具回“手机不在局域网”，助手据此告诉你。
- daemon 这边再校验一次：只把指令交给来自私有地址、不经 relay 的连接。插件 RPC 现在拿不到调用连接的来源，P1 要确认能否从宿主拿到；拿不到就只靠手机端判断，并在文档里写明。
- 每条指令有编号，手机按编号去重。发出后结果不明的动作（比如点了“发送”但回传丢了）标成“结果不明”，不自动重发，这是 mika 送达账本的规则。
- 每台手机注册成一个设备（设备 id 加名字），助手按名字选手机。

风险：Android 的省电模式（Doze）下，前台服务里的 JS 长轮询是否稳定要实测。不稳就把长轮询挪到原生层，代价是在 Kotlin 里再实现一遍 Paseo 的连接，工作量很大；只限局域网后不需要 relay 加密，比原来轻一些。

## Spark 端（Bigbang 插件）

工具名遵守 `^[a-z][a-z0-9_]{0,40}$`，对外显示为 `bigbang-phone_*`：

| 工具                                                                   | 作用                                               |
| ---------------------------------------------------------------------- | -------------------------------------------------- |
| `phone_devices`                                                        | 列出可用的手机和状态                               |
| `phone_observe`                                                        | 读当前屏：精简控件树、元素编号、前台 App，可附截图 |
| `phone_tap`、`phone_type`、`phone_scroll`、`phone_swipe`、`phone_back` | 基本操作，按元素编号或坐标                         |
| `phone_launch_app`、`phone_list_apps`                                  | 打开 App、列出 App                                 |
| `phone_steps`                                                          | 一次做 1–20 个已知动作，每步可带等待条件（P2）     |
| `phone_collect`                                                        | 逐屏读长列表或聊天并去重合并（P2）                 |
| `phone_hand_to_user`                                                   | 交给用户处理登录、验证码、付款（P2）               |

- **30 秒上限**：插件工具调用超过 30 秒会失败（[plugins.md](plugins.md#agent-tools)），所以每个工具都要在一次调用内做完，`phone_steps` 总时长限制在 25 秒以内。
- **授权**：照 Bigbang 任务工具的做法，按账本授权：调用者的 Chat 会话、助手单独开启的手机权限（默认关）、允许哪几台手机、当前有正在进行的回复回合。工具输入里的名字不算授权。
- **截图给模型**（已定：扩展插件工具合同）。现在插件工具的返回值是按 `output` schema 校验的 JSON，`packages/server/src/server/plugins/agent-tools.ts` 的 `toToolResult` 把它包成一段 `text` 加 `structuredContent`，没有图片。daemon 自带的 MCP 工具已经能返回 `image` 内容，所以只改插件这一层：
  - `@getpaseo/plugin` 加一个结果包装，handler 可以在 JSON 之外附带图片（`data` 为 base64、`mimeType`），`output` schema 只校验 JSON 部分；
  - 插件进程经 IPC 把图片带回，`toToolResult` 把它们追加成 MCP `image` 内容；
  - 写进 [plugins.md](plugins.md#agent-tools) 和公开的插件参考。这是 Paseo 本体的改动，以后可以作为上游 PR。
  - 截图压到长边 1080、JPEG，控制单张大小和 IPC 负担。平时主要靠控件树，截图按需附带。
  - P0 要实测 Codex、Claude、Grok 各自是否把 MCP 图片交给模型看；不支持的那家只拿到控件树。

## Chat 界面

- 助手操作手机时，回复气泡上方显示后台屏的小画面（最近一帧，点开放大）和已做的步骤。
- 需要你处理时（登录、验证码、付款），Chat 里出卡片，手机上同时发通知；点“我来处理”，App 从虚拟屏挪到主屏，处理完交还。
- Chat 的停止按钮同时取消手机上排队中和进行中的指令。

## 安全

被控手机上有微信和支付，等于让 Spark 上的模型能动这些 App。

- 默认关：手机上一个总开关，加每个助手单独授权。
- 付款、下单只能在被控手机本机上确认；从 Chat、Spark 或电脑一律不能放行（mika 的规则）。
- 屏幕内容一律当作不可信数据交给模型，不从屏幕内容写记忆。
- 同一个 App 里连续的发送类动作之间留间隔（mika 的 `OutwardPacing`）。
- 设了禁止截屏的页面（支付、密码）读不到，直接交给用户。
- 配对钥匙存在 Android Keystore 包装的私有文件里。

## 分阶段

| 阶段          | 内容                                                                                                                     | 验收                                                                                                            |
| ------------- | ------------------------------------------------------------------------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------- |
| P0 adb 原型   | 不改 App：Spark 经无线 adb 连手机，插件用 adb 截图、导出控件树、模拟点按，包成上面的基本工具；扩展插件工具合同以返回截图 | 助手在 Chat 里完成“看电池百分比”“给文件传输助手发一句话”；插件工具合同能返回截图，三家模型各自是否看得到        |
| P1 手机端基础 | 原生模块：内置助手、虚拟屏、无障碍、长轮询、基本工具；Chat 里的小画面                                                    | 在手机上的 Chat 发话，助手在后台屏办完，主屏不受影响；离开局域网（经 relay）时手机工具拒绝执行，Chat 里说明原因 |
| P2 进阶       | `phone_steps`、`phone_collect`、接管、付款确认、节奏、mika 的 App 使用知识                                               | 读完一个微信群今天的消息并总结；付款停在手机确认                                                                |
| P3 可选       | 文字识别、多台手机、定时任务里用手机                                                                                     | 按需定                                                                                                          |

P0 直接操作前台屏，会和你抢屏幕，换 Wi-Fi 或重启后要重新连 adb，只用来验证效果。
